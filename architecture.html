01 — Tech Stack
What Technologies Were Used?
Every tool chosen for a specific reason — building a production-style web app from scratch.
🌐
Frontend
HTML + CSS + JavaScript
The three pillars of the web. HTML = structure, CSS = design, JS = interactivity. You already know these!
⚡
Backend
Node.js + Express.js
Node.js runs JavaScript on the server. Express.js is a framework that makes it easy to create API endpoints.
🍃
Database
MongoDB + Mongoose
MongoDB stores data as JSON-like documents (similar to Python dicts). Mongoose helps JavaScript talk to MongoDB.
🔐
Auth & Security
bcryptjs + express-session
bcryptjs scrambles passwords so they can't be read. Sessions remember who is logged in between page loads.
🔗
Middleware
CORS + dotenv
CORS allows the browser to talk to the server safely. dotenv loads secret config values from a .env file.
🛠️
Dev Tools
Nodemon + npm
Nodemon auto-restarts the server when you change code. npm is the package manager that installs all libraries.

04 — User Flows
How a User Interacts with the App
Each flow shows the exact journey a user takes, which file handles each step, and what happens in the background.
Flow A — User Registration
1
User clicks "Register" button
A modal (popup window) opens on screen showing the registration form with Name, Email, and Password fields.
Frontendindex.html
2
User fills the form and clicks Submit
JavaScript collects the form data and sends a POST request (like submitting a form) to the backend server.
POST /api/auth/register → { name, email, password }
JavaScriptHTTP POST
3
Server receives and validates the data
Express route in auth.js checks if email already exists in MongoDB. If it does, it sends back an error message.
Expressroutes/auth.js
4
Password is hashed with bcrypt
The plain-text password "abc123" becomes something like "$2b$10$xKp…" — unreadable. This is called hashing. Even if the database is hacked, passwords stay safe.
Securitybcryptjs
5
User saved to MongoDB, session started
A new user document is created in the Users collection. The server also creates a session so the user stays logged in.
MongoDBSession
6
Success! UI updates to show logged-in state
Browser receives a success response. The navbar now shows the user's name and a Logout button appears.
FrontendUI Update
Flow B — Add to Cart & Place Order
1
User browses products page
JavaScript sends a GET request to fetch products from the server. Server queries MongoDB and returns product list as JSON.
GET /api/products?category=Electronics&sort=price
FrontendBackendMongoDB
2
User clicks "Add to Cart"
No server call here! The product is saved to localStorage in the browser. This is why cart works even when not logged in.
localStorage.setItem('cart', JSON.stringify(cartItems))
localStorageClient Only
3
User opens Cart and clicks "Place Order"
Must be logged in. JavaScript sends cart contents + shipping address to the server as a POST request.
POST /api/orders → { items, shippingAddress, paymentMethod }
HTTP POSTAuth Required
4
Server creates order & deducts stock
An Order document is saved in MongoDB. Each product's stock count is reduced by the quantity ordered. This is done in one operation to keep data accurate.
MongoDBorders.js
5
Order confirmed, cart cleared
Browser receives the order confirmation. localStorage cart is emptied. User sees a success toast notification and can view their order history.
UI UpdateToast Notification
05 — API Routes
All Backend Endpoints
An API (Application Programming Interface) is a set of URLs the frontend calls to get or send data. Think of them as doors into your server.
🔐 Auth Routes /api/auth
MethodEndpointWhat it does
POST/api/auth/registerCreate a new user account
POST/api/auth/loginLog in with email + password
POST/api/auth/logoutEnd the session (log out)
GET/api/auth/meGet currently logged-in user info auth
📦 Product Routes /api/products
MethodEndpointWhat it does
GET/api/productsList all products (supports filters, search, sort, pagination)
GET/api/products/:idGet a single product by its ID
POST/api/productsCreate new product admin
PUT/api/products/:idUpdate a product admin
DELETE/api/products/:idDelete a product admin
POST/api/products/seed/runLoad 12 sample products into database
🛒 Order Routes /api/orders
MethodEndpointWhat it does
POST/api/ordersPlace a new order auth
GET/api/orders/myView current user's order history auth
GET/api/orders/:idView details of a single order auth
GET/api/ordersView ALL orders (admin dashboard) admin
PUT/api/orders/:id/statusUpdate order status (e.g. "shipped") admin
06 — Database
MongoDB Schema Design
A Schema is like a blueprint — it defines what fields each record must have, just like a SQL table definition but more flexible.
👤
Users Collection
_idPK ObjectId
namerequired String
emailunique String
passwordhashed String
roleuser | admin
addressObject
createdAtDate (auto)
📦
Products Collection
_idPK ObjectId
namerequired String
descriptionString
pricerequired Number
categoryEnum (7 types)
stockNumber
ratingNumber (0–5)
imageString (URL)
🛒
Orders Collection
_idPK ObjectId
userFK → Users ObjectId
items[]Array of products
shippingAddressObject
totalPriceNumber
statuspending→delivered
paymentMethodCOD | UPI | Card
Relationships explained simply:
An Order has a user field that stores a User's _id — this is like a Foreign Key in SQL. It links the order to the person who placed it. Orders also have an items[] array that stores product details (name, price, quantity) directly inside the order document — so even if a product is deleted later, the order history is preserved.
